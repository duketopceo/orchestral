# feat: Evidence v2 — trustworthy measurement under the fixed harness

## Summary

The Grok 4.3 frontier review (132 runs: 48 invalid, 56 suspect, 28 clean) proved the existing leaderboard substantially measured harness bugs — empty artifacts from key mismatches, task briefs never reaching workers, blind candidate-picking, structural-only validators. Those bugs are now fixed (`f44ff41`, `7dd6436`). This phase closes the loop: deepen the remaining mechanical validation gaps the review surfaced, re-run the evaluation grids under the fixed harness so the leaderboard measures models, compare v1 vs v2, and publish scrubbed evidence.

Not in scope: new task types, new observability surfaces, rewriting historical labels.

## Problem Frame

`runs/` evidence is durable and well-labeled, but the numbers it produced were generated by a harness with verified assembly/context bugs. The published conclusions (e.g. "0/12 wall on constraint/needle/extract/sql") cannot be trusted until re-measured. Separately, the review flagged surviving validator gaps that are mechanically fixable:

- `multi-file` validation (`_validate_multi`) cannot inspect member contents — a zip with `index.html`/`style.css` present but unrelated content passes `has_paths` + `non_empty`.
- `batch-100` style generated specs and `multi-file-site` lack content anchors.
- Scrub coverage for newer artifact types (`artifact.diff`, `artifact.sql`, `review.json`) is unverified.

## Requirements

- R1: `multi-file` artifacts support member-content checks (`member_required`-style validation against extracted text members), so `multi-file-site` can require e.g. `coffee` in `index.html` and a `style.css` that isn't empty padding.
- R2: Task specs whose prompts name concrete nouns gain `has_required`/`required` anchors where a truthful artifact must contain them (multi-file-site; audit others; leave generated `batch-100` alone).
- R3: A v2 run group re-measures the `glm-vs-gemma` grid and the `deepseek+explicit` anchor under the fixed harness, same shapes as v1 for comparability (11 text tasks × 2 orchestrators × 2 workers × 3 replicates ≈ 132 runs + ~66 anchor runs; est. ≤ $0.65).
- R4: A v1→v2 delta report states which conclusions survived, which were harness artifacts, and which remain unresolved — written to `reports/` and summarized durably.
- R5: `harness.py scrub` verified to cover the new artifact/review files; scrubbed v2 evidence staged under `runs-pub/` with manifest.
- R6: Frontier review re-run over the v2 group (optional, ~$0.50) to check whether clean-rate recovers — dogfooding the loop a second time.

## Key Technical Decisions (KTDs)

- **KTD-1**: Content checks inside zips are implemented as a new validation name `member_required` in `_validate_multi` rather than overloading `has_required` — `has_required` operates on a decoded string artifact; multi-file artifacts are binary. `metadata.member_required: {"index.html": ["coffee", "pricing"], "style.css": ["hero"]}` maps member path → required substrings (case-insensitive). Unknown members listed in `member_required` are reported as errors, not silently skipped.
- **KTD-2**: v2 runs use new `run_group` labels (`glm-vs-gemma-v2`, `deepseek-explicit-v2`) — v1 labels untouched. Comparison is explicit grouping, never relabeling.
- **KTD-3**: Baseline is the current `feat/review-terminal-tasks` branch (contains all verified fixes). Merging PR #37/#38 to main stays with the user; measurement does not wait on it.
- **KTD-4**: Validator deepening is mechanical-only this phase. Judge-based semantic scoring + calibration stays a future phase; the review's `suggested_check` field already proved mechanical checks catch the real failures.
- **KTD-5**: n=3 replicates retained (same as v1) — comparability beats error-bar width for the v1→v2 question. n=10 is deferred to a later phase.

## Implementation Units

### U1 — `member_required` validation for multi-file artifacts

- `orchestral/runner.py` `_validate_multi`: when `member_required` in requested, extract listed members (text decode, cap at ~100KB per member), check each required substring case-insensitively; add to `known` set; report missing members and missing tokens distinctly.
- `orchestral/config.py` (or wherever validation-name contracts live): `member_required` requires `metadata.member_required` mapping; `harness.py validate` enforces the contract.
- `tasks/multi-file-site.yaml`: add `member_required` to validation + `metadata.member_required` entries for `index.html` (`coffee`, `pricing`) and `style.css` (`hero` or `pricing` — must exist in a truthful stylesheet).
- Tests: `tests/test_runner.py`-adjacent — member present with token passes; member missing → fail + error naming member; token absent → fail naming token; non-text member → honest error.

### U2 — Spec content-anchor audit

- Audit all `tasks/*.yaml` for prompts naming concrete required content lacking a matching check. Expected: `multi-file-site` (covered by U1). Verify `landing-page` variants and `batch-100` generator output stay as-is (generated specs inherit their own anchors — check `tools/` or wherever batch specs are generated; if the generator emits weak specs, fix the generator not the outputs).
- `harness.py validate` already enforces per-type metadata contracts — extend only if a spec class is found uncheckable.

### U3 — v2 measurement runs (operational)

- `python3 harness.py run` grid mirroring the v1 `glm-vs-gemma` shape under `--group glm-vs-gemma-v2` (check `harness.py` grid/batch flags used to create v1; replicate exact task × orchestrator × worker matrix at n=3).
- `deepseek+explicit` anchor under `--group deepseek-explicit-v2`.
- Runs execute from this branch head. Record actual spend vs estimate in the delta report.

### U4 — v1→v2 delta + frontier re-review

- `harness.py report --groups` (or equivalent) comparing v1 vs v2 pass rates per task family.
- Write `reports/v2-delta-<ts>.md`: per-family pass-rate delta, which v1 failures flipped (harness-artifact class), which persisted (model-capability class), unresolved list. Keep it generated-by-command where possible so it's reproducible.
- `harness.py review --model x-ai/grok-4.3 --group glm-vs-gemma-v2` over the new group; compare clean/suspect/invalid distribution vs v1's 28/56/48.

### U5 — Scrub + publish evidence

- Verify `orchestral/privacy.py` `scrub_all` covers `artifact.diff`, `artifact.sql`, `artifact.txt`, `review.json`, `calls.jsonl`, `debug.jsonl` — extend the file map where a v2 artifact type is missed.
- `harness.py scrub` → `runs-pub/` for the v2 groups + manifest.
- README/docs note pointing at the v2 evidence and delta report.

## Scope Boundaries

- No new task types, no new observability surfaces (TUI/web/dashboard untouched).
- Historical runs and labels untouched — v1 evidence stays as archived with its `git_commit` pins.
- No merge to main; PR merge decisions stay with the user.
- No judge/calibration work; no n=10 replicates.
- Spend ceiling ~$1.15 total (grid $0.35 + anchor $0.30 + review $0.50).

## Assumptions (recorded under pipeline posture — user may correct)

- A1: Re-run extent = cheap grid + anchor (~$0.65), not the n=10 deep run. Rejected alternative: n=10 now — deferred, comparability with v1 (n=3) matters more than tighter error bars for the delta question.
- A2: Validator depth = mechanical-only. Rejected alternative: judge-based semantic scoring now — heavier build, and the review showed mechanical checks catch the failure classes that mattered.
- A3: Baseline = current branch, not post-merge main. Rejected alternative: wait for #37/#38 merges — measurement shouldn't block on user's merge decision.
- A4: Publication ships in this phase (scrub + manifest + delta report). Rejected alternative: defer publication — the v2 evidence is the deliverable, not an intermediate.

## Risks

- Grid re-run takes ~75+ min wall-clock at real-model latency; run in background and poll. `--dry-run` first to verify plumbing.
- `member_required` on binary members (images inside a zip) must error honestly, not crash — decode errors reported per member.
- If v2 pass-rates barely move, the delta report must say so plainly — that result is itself evidence the harness fixes mattered less than the review suggested; do not spin it.
- Reviewer model drift: `grok-4.3` output distribution may differ across days; compare verdict mix directionally, not as ground truth.
